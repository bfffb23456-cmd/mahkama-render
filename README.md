# قاعة المحاكمة — Render

## النشر
1. ارفع محتويات هذا المجلد إلى مستودع GitHub.
2. في Render اختر New > Blueprint واربط المستودع.
3. وافق على `render.yaml` ثم انتظر النشر.

## تشغيل محلي
`pip install -r requirements.txt` ثم `python app.py` وافتح `http://localhost:5000`.

## ملاحظات
- المقدم ينشئ جلسة ويرسل رابطًا منفصلًا لكل مجموعة.
- كل مجموعة تسجل اسمها وأعضاءها، وتكتب الجاني والسبب والتناقضات والملاحظة وتجهيز المحاججة.
- توزيع المواجهة ثابت: 1 تعارض 2، و2 تعارض 3، و3 تعارض 1.
- الدرجات: الجاني 10، السبب 30، التناقضات 15، الملاحظة 5، الإلقاء 20، المحاججة 20.
- لا تظهر الإجابات أو النتائج للاعبين. المقدم وحده يرى مفتاح الحل ويرصد الدرجات.
- المؤشر الآلي الحالي لا يفهم المعنى؛ هو مؤشر أولي لتشابه الكلمات فقط. الدرجة النهائية للمقدم.
- بنك القضايا الحالي سيناريوهات تعليمية مركبة/خيالية، وليس 30 قضية تاريخية موثقة. لا تقدّمها على أنها قضايا حقيقية.
- احتفظ برابط المقدم ولا تشاركه. قرص Render الدائم مفعّل لحفظ SQLite.

## تخزين Render
يستخدم هذا الإعداد قرصًا دائمًا لحفظ جلسات اللعبة، وRender يشترط خدمة ويب مدفوعة لاستخدام الأقراص الدائمة. إذا أزلت القرص واستخدمت خدمة مجانية، فملف SQLite قد يُمسح عند إعادة التشغيل أو النشر؛ لا تعتمد على ذلك لحفظ جلسة مهمة.
